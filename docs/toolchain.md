# Compiler-paired toolchain metadata

Shuttle selects the standard library through `cloth-toolchain.json` beside the
canonical selected `clothc` executable. It does not search the working
directory, environment variables, user home, or network.

Schema 1 is:

```json
{
  "schema": 1,
  "standard_library": {
    "package": "cloth",
    "version": "0.6.0",
    "manifest": "standard-library/Shuttle.toml"
  }
}
```

`manifest` is a normalized `/`-separated path relative to the compiler
directory. A development build may begin it with `..` to select the checked-out
`std` submodule. Released toolchains should point it into their bundled
distribution. Absolute paths, backslashes, normalization aliases, unknown
fields, and files other than exact `Shuttle.toml` are rejected.

The package and version must exactly match the compiler capability response.
The selected manifest must define only the executable-free `cloth` package at
that version, with no dependencies. Shuttle compiles it without a self-edge and
adds `cloth -> cloth` directly to every ordinary package. Existing artifact
digests, receipts, transitive closure, cache validation, and linking then carry
the selected library without a second artifact mechanism.

Users do not edit this file and do not list `cloth` in `[dependencies]`. A
missing or invalid paired distribution is a toolchain error, not a project
dependency-resolution fallback.
